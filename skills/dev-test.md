# Skill: dev-test

DE 开发自测标准操作规程。编码完成后、提交回报前必须执行。

---

## 触发时机

DE 完成编码实现后，在填写 code-report.md 之前执行。

## Step 1: 单元测试执行

1. 检测项目测试框架（package.json 中的 test script）
2. 运行全量单元测试
3. 记录结果：通过数 / 失败数 / 跳过数
4. 如有失败：修复代码，重新运行，直到全部通过

## Step 2: Lint 检查

1. 检测项目 lint 工具（eslint / prettier 等）
2. 运行 lint 检查
3. 自动修复可修复项
4. 如有不可自动修复的问题：手动修复

## Step 3: 构建验证

1. 执行项目构建命令（build script）
2. 确认构建成功，无错误输出
3. 构建失败则修复后重试

## Step 4: 自检清单

逐项确认：

- [ ] 所有新增代码有对应测试
- [ ] 测试全部通过
- [ ] Lint 无错误
- [ ] 构建成功
- [ ] 未修改白名单外的文件
- [ ] 未引入新的安全漏洞（无硬编码密钥、无 SQL 拼接等）

## 输出

将结果记录到 deliverables/de/code-report.md 的"测试结果"和"自检结果"部分：

```
## 测试结果
- 测试数: {N}
- 通过: {N}
- 失败: 0

## 自检结果
- dev-test: PASS
```

## 失败处理

- 任何一步失败：修复后从该步重新执行
- 修复 3 次仍失败：在 handoff 回报中标记 status=failed，附带错误日志
