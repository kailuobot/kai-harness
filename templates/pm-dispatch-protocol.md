# PM 调度协议

PM 执行任何 skill 时，必须遵循本协议。本文件是 PM 调度行为的唯一标准。

---

## 调度循环（标准 8 步）

```
1. 读取 .state.md         → 确认当前位置（phase/step/repair_round）
2. 写入 handoff           → 使用 templates/handoff-template.md 格式
3. 检查停止条件           → 触发则暂停等待用户
4. 更新 .state.md         → current_step/current_role/current_handoff
5. 派发 SubAgent          → 注入 agent 契约 + handoff + 白名单文件
6. 接收回报               → SubAgent 填写 handoff 完成回报
7. 执行质量门禁           → 按 agents/pm.md 中对应角色的检查清单逐项核对
8. 推进或驳回             → 通过则更新 .state.md 进入下一步；不通过则写新 handoff 驳回
```

每一步之间打印心跳：`[PM] {动作描述}`

---

## 停止条件（PM 必须暂停等待用户）

| 条件 | 触发场景 | PM 行为 |
|------|---------|---------|
| SR Gate 阻塞 | SR1/SR2/SR3/SR4 节点 | 呈现决策上下文卡，等待用户通过/驳回 |
| 修复循环发散 | repair_history 显示连续 2 轮发散 | 呈现修复历史，上升人工判断 |
| 人机协作步骤 | Proposal 确认、模式选择、wireframe 审批 | 呈现选项，等待用户决策 |
| SubAgent 连续失败 | 同一步骤 repair_round ≥ 5 | 呈现失败摘要，上升人工 |

---

## 质量门禁执行指引

PM 接收 SubAgent 回报后，按以下步骤执行质量门禁：

1. **文件存在性**：确认期望输出文件存在且非空
2. **内容质量快扫**：打开 `agents/pm.md` 中对应角色的质量门禁清单，逐项检查
3. **判定**：
   - 全部通过 → 更新 .state.md，推进下一步
   - 任一不通过 → 写新 handoff 驳回，附带：
     - 哪些检查项未通过
     - 具体缺陷位置（文件+章节）
     - 期望的修正方向

---

## 心跳打印规范

PM 在以下时机打印心跳（格式: `[PM] {描述}`）：

- 流程启动: `[PM] /mh-{command} 流程启动，REQ-ID: {REQ-ID}`
- 调度角色: `[PM] 调度 {role} 执行 {任务类型}`
- 角色完成: `[PM] {role} {任务类型}完成，产物已验证`
- 质量门禁: `[PM] 质量门禁通过` 或 `[PM] 质量门禁未通过，驳回 {role}`
- 审批节点: `[PM] 进入 {SR-N} 人工审批`
- 审批结果: `[PM] {SR-N} 通过` 或 `[PM] {SR-N} 驳回，回退到 {step}`
- 修复循环: `[PM] Task-{N} 审计失败（轮次 {R}/5，{收敛/发散}）`
- 流程结束: `[PM] /mh-{command} 流程完成`

---

## 六条铁律（调度时自检）

| # | 铁律 | 违反时的处理 |
|---|------|-------------|
| ① | 严格顺序（跳过≠乱序） | 阻塞，提示用户先完成前序阶段 |
| ② | PM 只做调度 | 不对产出物内容做技术判断 |
| ③ | 每棒必须有 handoff | 无 handoff 不得派发 SubAgent |
| ④ | SR 不可自主跨越 | 必须等待用户明确通过 |
| ⑤ | 下游不改上游 | 驳回时创建新 handoff，不修改已有文件 |
| ⑥ | 心跳 ↔ 动作一对一 | 每个动作前打印心跳 |
