# v0.6.0 数据驱动优化计划

基于 REQ001 实战数据 + metrics-analysis-REQ001.md 分析，本轮优化聚焦三个核心问题：
1. Handoff 完成回报机制失效（角色隔离协议的核心缺陷）
2. PM 心跳/日志不落盘（断点恢复和审计基础缺失）
3. 归档质量控制缺失（.venv 混入、spec/ 不完整、SR3 标准过刚性）

---

## 改动清单

### P0-1: Handoff 完成回报强制机制

**问题**: 所有 5 个 handoff 的完成回报区域为空。SubAgent 写了产出文件但没回填 handoff。
**根因**: SubAgent 在独立子会话中运行，写入产出文件后直接结束，没有回到 handoff 填写回报。

**改动文件**: 
- `templates/handoff-template.md` — 完成回报区增加醒目强制提示
- `agents/pm.md` — 调度循环 Step 6 增加"回报缺失时 PM 代填"逻辑
- `scripts/verify.sh` — C 类检查增加"handoff 完成回报非空"校验

**具体设计**:

1. handoff-template.md 完成回报区改为：
```markdown
## 完成回报（执行角色必填 — 未填写则任务视为未完成）

<!-- ⚠️ SubAgent 必须在结束前填写本节，否则 PM 将驳回 -->
- status: {done | failed}
- output_files: ["{file_path}"]
- read_files: ["{实际读取的文件路径}"]
- summary: "{一句话描述完成内容}"
- issues: "{错误信息或 N/A}"
```

2. agents/pm.md 调度循环 Step 6 增加回报缺失处理：
```
6. 接收回报 → SubAgent 填写 handoff 完成回报
   - 如回报为空（status/output_files/summary 均未填写）：
     PM 根据产出文件实际情况代填回报（读取 output/ 文件列表 + code-report/test-report 摘要）
     标注: "[PM 代填] SubAgent 未回报，PM 根据产出物推断"
   - 如 status=failed：进入修复循环
```

3. verify.sh C 类新增检查（phase=done 时）：
```bash
# Handoff 完成回报非空检查
for handoff in "$handoff_dir"/*.md; do
    if grep -q "^status: pending" "$handoff" 2>/dev/null; then
        echo "WARN: $(basename "$handoff") 仍为 pending（完成回报未填写）"
    fi
    if grep -q '^summary: ""' "$handoff" 2>/dev/null || grep -q "^summary: $" "$handoff" 2>/dev/null; then
        echo "WARN: $(basename "$handoff") summary 为空"
    fi
done
```

### P0-2: process.log 强制落盘

**问题**: process.log 仅 2 行，PM 心跳只打印到 stdout 没有写入文件。
**根因**: logging-standard.md 定义了规范但 skills 中没有强制要求"写入文件"的具体指令。

**改动文件**:
- `templates/logging-standard.md` — 增加强制落盘指令
- `skills/mh-apply.md` — 在关键步骤增加显式日志写入提示
- `skills/mh-propose.md` — 同上
- `scripts/verify.sh` — C 类检查增加 process.log 行数下限

**具体设计**:

1. logging-standard.md 增加：
```markdown
**强制落盘规则：**
- PM 的每条心跳 `[PM] xxx` 必须同时执行: `echo "[{timestamp}] [PM] xxx" >> deliverables/{REQ-ID}/process.log`
- SubAgent 完成时追加一条: `echo "[{timestamp}] [{角色}] 完成 {task_id}，产出: {file_list}" >> deliverables/{REQ-ID}/process.log`
- 心跳仅打印到 stdout 而未写入 process.log 视为违规

**最低行数要求（phase=done 时）：**
- fast 模式: ≥ 6 行（init + dev + test + confirm + archive + done）
- standard/full 模式: ≥ 10 行
```

2. verify.sh C 类新增：
```bash
# process.log 完整性检查
if [ "$phase" = "done" ]; then
    local log_file="$REQ_DIR/process.log"
    if [ ! -f "$log_file" ]; then
        echo "FAIL: phase=done 但 process.log 不存在"
        ERRORS=$((ERRORS + 1))
    else
        local log_lines
        log_lines=$(wc -l < "$log_file" | tr -d ' ')
        local min_lines=10
        [ "$mode" = "fast" ] && min_lines=6
        if [ "$log_lines" -lt "$min_lines" ]; then
            echo "WARN: process.log 仅 $log_lines 行（$mode 模式期望 ≥$min_lines）"
        else
            echo "PASS: process.log $log_lines 行"
        fi
    fi
fi
```

### P1-1: SR3 覆盖率标准弹性化

**问题**: SR3 标准写死"覆盖率 = 100%"，但实际 93% 也通过了。标准与执行不一致。

**改动文件**: `skills/mh-apply.md` — SR3 通过标准修改

**具体设计**:

将 SR3 通过标准从：
```
- [ ] 需求覆盖无遗漏（覆盖率 = 100%）
```
改为：
```
- [ ] 需求覆盖率 ≥ 95%，且未覆盖项均有降级机制或补充计划
```

SR3 决策上下文卡增加：
```
降级项确认（如有）:
  - {未覆盖需求}: {降级机制/补充计划}
```

### P1-2: 归档排除规则

**问题**: .venv/ 被归档到 output/，产出物体积膨胀。

**改动文件**: `skills/mh-archive.md` — ARC-3 增加排除规则

**具体设计**:

ARC-3 步骤 4（首次归档）和步骤 5（变更归档）之间插入排除规则：

```markdown
> 归档排除规则（复制时跳过以下目录/文件）：
> .venv/, node_modules/, __pycache__/, .pytest_cache/, .ruff_cache/,
> .git/, .DS_Store, *.pyc, *.pyo, .env
```

同时在 verify.sh B 类增加检查：
```bash
# 产出物中不应包含开发环境目录
for excluded in .venv node_modules __pycache__ .pytest_cache; do
    if [ -d "$OUTPUT_DIR/$excluded" ]; then
        echo "WARN: output/ 包含 $excluded/（应排除的开发环境目录）"
    fi
done
```

### P1-3: spec/ 归档完整性校验

**问题**: spec/ 下只有 _templates/，requirement-spec.md 和 design.md 没有被归档。

**改动文件**: `scripts/verify.sh` — B 类检查增强

**具体设计**:

verify.sh B 类在 phase=done 时增加：
```bash
# spec/ 归档完整性（full/standard 模式）
if [ "$phase" = "done" ] && [ "$mode" != "fast" ]; then
    if [ ! -f "spec/design.md" ]; then
        echo "WARN: spec/design.md 不存在（ARC-2 归档可能未执行）"
    fi
    if [ "$mode" = "full" ] && [ ! -f "spec/requirement-spec.md" ]; then
        echo "WARN: spec/requirement-spec.md 不存在（ARC-1 归档可能未执行）"
    fi
fi
```

### P2-1: Agent 超时处理规则

**问题**: 3/14 任务超时（21%），框架没有定义"超时但代码完整"的处理规则。

**改动文件**: 
- `skills/mh-apply.md` — 异常处理节增加超时处理
- `agents/de.md` — 增加超时前保底行为

**具体设计**:

mh-apply.md 异常处理节增加：
```markdown
- SubAgent 超时但产出物已存在:
  - PM 检查 output/ 中对应 Task 的文件是否完整（与 plan-action.md 描述匹配）
  - 完整 → 视为成功，PM 代填 code-report（标注"[PM 代填] Agent 超时，产出物完整"）
  - 不完整 → 重试一次
```

### P2-2: 多 Task 合并 code-report 规范化

**问题**: T-12/T-13/T-14 合并为一个 code-report，违反逐 Task 独立约定。

**改动文件**: `skills/mh-apply.md` — 并行批次开发节增加说明

**具体设计**:

```markdown
> code-report 规则：每个 Task 独立 code-report（`code-report-t{N}.md`）。
> 同批并行的 Task 不得合并 code-report。如 SubAgent 合并产出，PM 在质量门禁时要求补充独立报告。
```
